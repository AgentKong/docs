# Available Tools

The AI discovers these tools automatically via MCP. Just ask questions in natural language.

## get\_attribution

Full attribution table with drill-down by source, campaign, medium, and ad.

| Parameter | Type | Required | Description |  |  |  |
| --- | --- | --- | --- | --- | --- | --- |
| `startDate` | string | Yes | Start date ISO 8601 |  |  |  |
| `endDate` | string | Yes | End date ISO 8601 |  |  |  |
| `groupBy` | enum | No | `source`, `campaign`, `medium`, `ad`. Default: `source` |  |  |  |
| `attributionModel` | enum | No | `last_click`, `first_click`, `paid_priority`, `scientific` |  |  |  |
| `sources` | string | No | Pipe-separated: \`"Meta Ads |  |  | Google Ads"\` |
| `campaigns` | string | No | Pipe-separated filter |  |  |  |
| `currency` | string | No | Currency code. Default: `USD` |  |  |  |
| `timezone` | string | No | IANA timezone. Default: `America/New_York` |  |  |  |

**Returns:** pageViews, leads, conversions (per event type with count/revenue), totalRevenue, totalLTV, ROAS, ROI, costPerConversion, ad spend.

<Accordion title="Drill-down workflow">
  1. Start with `groupBy=source` to see top-level channels
  2. Filter by a source → switch to `groupBy=campaign`
  3. Filter by campaign → switch to `groupBy=ad` for individual ad performance
</Accordion>

## get\_meetings

Fathom meeting recordings — sales call data including transcripts, AI summaries, attendees, action items, and structured insights (problems, pain points, objections, prospect questions, next steps).

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `mode` | enum | Yes | `list`, `get`, `transcript`, `insights` |
| `meetingId` | string | For get/transcript | Meeting ID |
| `contactId` | string | No | Filter by contact |
| `callTypeId` | string | No | Filter by call type ID |
| `salesRepEmail` | string | No | Filter by recorded-by email |
| `outcome` | enum | No | `PURCHASED`, `VERBAL_COMMIT`, `PROPOSAL_REQUESTED`, `FOLLOW_UP_SCHEDULED`, `UNDER_REVIEW`, `STALLED`, `LOST`, `NO_DECISION` |
| `isStructured` | string | No | `true` / `false` — meetings with structured insights extracted |
| `fromDate` / `toDate` | string | No | ISO 8601 date range — filters by meeting date |
| `limit` | number | No | List mode page size (max 50, default 20) |
| `cursor` | string | No | Pagination cursor for list mode |

<Accordion title="Mode details">
  - **list** — Meeting metadata (title, date, duration, attendees, outcome, call type, recorded-by, insight counts). Paginated with cursor.
  - **get** — Single meeting with full structured data: `conversationSummary`, `problems`, `painPoints`, `objections`, `prospectQuestions`, `nextSteps`, `summary`, `actionItems`, `attendees`. Requires `meetingId`.
  - **transcript** — Full transcript with `speaker`, `timestamp`, and `text` per entry. Up to 2 MB per meeting. Requires `meetingId`.
  - **insights** — Aggregated breakdown across many meetings: top `problems` / `painPoints` / `objections` / `prospectQuestions` (with frequency and sample meeting IDs), plus `callTypeBreakdown`, `outcomeBreakdown`, and `salesRepBreakdown`. Use date filters to scope.
</Accordion>

**Example response (insights mode):**

```json
{
  "data": {
    "totalMeetings": 156,
    "structuredMeetings": 142,
    "truncated": false,
    "callTypeBreakdown": [
      { "callType": "Sales Call", "count": 89 },
      { "callType": "Discovery", "count": 45 }
    ],
    "outcomeBreakdown": [
      { "outcome": "FOLLOW_UP_SCHEDULED", "count": 62 },
      { "outcome": "PURCHASED", "count": 18 }
    ],
    "salesRepBreakdown": [
      { "email": "luis@usecortana.ai", "name": "Luis Vasquez", "count": 87 }
    ],
    "aggregatedInsights": {
      "problems": [
        { "text": "Manual attribution tracking is broken", "frequency": 23, "sampleMeetingIds": ["..."] }
      ],
      "painPoints": [...],
      "objections": [...],
      "prospectQuestions": [...]
    }
  }
}
```

<Tip>
  **Workflow:** Use `list` to find meetings → `get` for full structured data → `transcript` for the actual conversation. Use `insights` for "what are prospects saying?" type questions across many meetings.
</Tip>

<Tip>
  The `insights` mode scans up to 5,000 meetings per call. Use `fromDate` / `toDate` to scope larger histories.
</Tip>

## get\_form\_submissions

Booking-form submissions (leads) — anyone who filled out a booking form at any stage (partial, submitted, or booked). Includes the exact answers the visitor submitted (`formData`) plus their attribution (UTMs, click IDs, referrer).

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `mode` | enum | Yes | `list`, `get` |
| `submissionId` | string | For get | Form submission ID |
| `status` | enum | No | `POTENTIAL`, `QUALIFIED`, `DISQUALIFIED`, `BOOKED`, `PARTIAL`, `SUBMITTED` — `PARTIAL` = started, `SUBMITTED` = completed form, `BOOKED` = booked a slot |
| `eventTypeId` | string | No | Filter by event type (which booking form) |
| `contactId` | string | No | Filter by contact |
| `from` / `to` | string | No | ISO 8601 date range — filters by submission date (`createdAt`) |
| `sort` | string | No | `createdAt` or `-createdAt` (default newest first) |
| `limit` | number | No | List mode page size (max 100, default 20) |
| `page` | number | No | Page number |

<Accordion title="Mode details">
  - **list** — Form submissions matching your filters. Each row has `name` / `email` / `phone`, the submitted `formData`, `attribution`, `status`, and `convertedToAppointmentId` when the lead booked. Paginated.
  - **get** — A single submission by id, full detail. Requires `submissionId`.
</Accordion>

**Example response (list mode):**

```json
{
  "data": [
    {
      "id": "a1b2c3d4-...",
      "eventTypeId": "evt_...",
      "eventTypeName": "Discovery Call",
      "contactId": "ctc_...",
      "status": "SUBMITTED",
      "name": "Jane Doe",
      "email": "jane@example.com",
      "phone": "+15551234567",
      "formData": {
        "What's your monthly ad spend?": "$10k–$25k",
        "Biggest challenge": "Attribution is broken"
      },
      "attribution": {
        "utmSource": "facebook",
        "utmMedium": "paid",
        "utmCampaign": "q2-leadgen",
        "fbclid": "IwAR...",
        "referrer": "https://facebook.com",
        "landingPage": "https://acme.com/book"
      },
      "convertedToAppointmentId": null,
      "createdAt": "2026-06-21T14:03:00.000Z",
      "updatedAt": "2026-06-21T14:03:00.000Z"
    }
  ],
  "pagination": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

<Tip>
  **Workflow:** Use `status: "SUBMITTED"` (or `PARTIAL`) to find leads who filled the form but have no `convertedToAppointmentId` yet — i.e. submitted but never booked. Filter by `eventTypeId` to scope to one booking form.
</Tip>

# YouTube Organic Tools

These 7 tools query the YouTube data ingested by the YouTube Organic integration — channel rollups, video metrics, retention curves, transcripts, and AI-generated insight narratives. All scoped to the authenticated business.

<Tip>
  **Prefer `get_youtube_channel_metrics` over summing per-video calls.** Channel rollups are an authoritative aggregate maintained by the daily sync. Per-video summing can drift because some channel views don't tie to a specific video (deleted videos, channel-page traffic, etc.).
</Tip>

## list\_youtube\_channels

Connected & selected YouTube channels with last-30-day performance summary.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| _(none)_ | — | — | Returns all selected channels for the business |

**Returns:** array of channels, each with `subscriberCount`, lifetime `viewCount`, `videoCount`, `syncStatus`, plus `last30d.{ views, estimatedMinutesWatched, subscribersGained, topTrafficSource }`.

<Tip>
  Always start here — every other YouTube tool needs an internal `channelId` from this response (NOT the platform `UC...` id).
</Tip>

## get\_youtube\_channel\_metrics

Channel-level totals \+ daily breakdown for any custom date range. Reads directly from the channel rollup table — one call answers "last 7 days," "this month," etc.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `channelId` | string | Yes | Internal channel id from `list_youtube_channels` |
| `from` | string | No | Start date `YYYY-MM-DD`. Default: 30 days ago |
| `to` | string | No | End date `YYYY-MM-DD`. Default: yesterday |
| `includeDaily` | boolean | No | Include the daily array. Default: `true` |

**Returns:**

```json
{
  "channel": { "id": "...", "name": "Matei Parvu", "platformChannelId": "UC..." },
  "range":   { "from": "2026-04-22", "to": "2026-04-28", "days": 7 },
  "total": {
    "views": "48",
    "estimatedMinutesWatched": "39",
    "likes": "0",
    "comments": "0",
    "shares": "0",
    "subscribersGained": "0",
    "subscribersLost": "0",
    "averageViewDuration": 49
  },
  "daily": [{ "date": "2026-04-22", "views": "...", ... }, ...]
}
```

<Tip>
  Use `includeDaily: false` for cheap totals when you don't need the day-by-day series.
</Tip>

## get\_youtube\_video

Full detail for one video.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `videoId` | string | Yes | Internal video id (NOT the 11-char platform id) |

**Returns:** all video metadata, channel info, all transcripts (`language`, `fullText`, `segments`), latest retention curve, AI insight (if generated — see [insights](#get_youtube_video) note below), and three rollup windows: `lifetime`, `last30d`, `last7d`.

<Tip>
  The `insight` field is populated by the nightly insight worker (08:00 UTC). It contains an AI-written 1-3 paragraph performance narrative \+ a structured `summaryJson` with topTrafficSource, retentionDropoffRatio, etc. Requires `ANTHROPIC_API_KEY` to be configured.
</Tip>

## get\_youtube\_metrics

Per-video analytics sliced by a dimension — daily time-series or breakouts.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `videoId` | string | Yes | Internal video id |
| `dimension` | enum | Yes | `day`, `trafficSource`, `device`, `country`, `demographics` |
| `from` | string | No | `YYYY-MM-DD`. Default: 30 days ago |
| `to` | string | No | `YYYY-MM-DD`. Default: yesterday |

**Dimension behaviour:**

<Accordion title="Dimension details">
  - **day** — daily time-series of views, watch time, likes, comments, subs gained
  - **trafficSource** — `YT_SEARCH`, `EXT_URL`, `SUGGESTED_VIDEO`, `YT_OTHER_PAGE`, etc.
  - **device** — `DESKTOP`, `MOBILE`, `TABLET`, `TV`
  - **country** — single snapshot keyed at the period end (YouTube's API rejects `day,country` as a query shape, so we store a snapshot per backfill)
  - **demographics** — `viewerPercentage` by age × gender, refreshed weekly when the snapshot is older than 7 days
</Accordion>

## get\_youtube\_transcript

Full transcript text \+ timestamped segments for a video.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `videoId` | string | Yes | Internal video id |
| `language` | string | No | Language code (e.g. `en`). Omit for the best available |

**Returns:** `language`, `isAutoGenerated`, `fullText`, `segments[]` where each segment is `{ start, dur, text }`.

<Tip>
  Picks the best transcript automatically: human-authored over auto-generated, then English over other languages.
</Tip>

## search\_youtube\_videos

Full-text search across the user's YouTube videos. Backed by MySQL FULLTEXT indexes covering **title \+ description \+ hook** (on the videos table), **transcript fullText**, and **insight narrative**.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `query` | string | Yes | Search query, min 2 chars. MySQL natural-language mode |
| `limit` | number | No | 1-50. Default: `10` |

**Returns:** matching videos with `title`, channel name, `publishedAt`, `viewCount`, and `matchedIn` (`'video' | 'transcript' | 'insight'`) so you know whether the search hit metadata, transcript, or AI analysis text.

<Tip>
  This is the entry point for "find videos that mention X" questions. The AI typically follows up with `get_youtube_video` on the top match for full detail.
</Tip>

# Checkouts and products

New. Build and manage Cortana embedded checkouts, and create Stripe products on the fly. The two read tools are available as soon as you connect. The four write tools require the manage opt-in on the consent screen (the same checkbox that unlocks ad management). A Cortana embedded checkout carries attribution, rep credit, and commissions by itself, so when an assistant builds a page that sells, it should create one of these instead of wiring a bare Stripe checkout.

<Warning>
  `create_embedded_checkout` produces a checkout that is live immediately. Check the `livemode` flag in the response to know whether it can take real money.
</Warning>

## get\_embedded\_checkouts

List this business's embedded checkouts, each with its config, funnel stats, livemode label, and paste-ready embed snippet. Read scope: `checkouts:read`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID. Omit if the key is scoped to one business. |
| `id` | string | No | A specific checkout id. Returns just that one. |
| `page` | integer | No | Page number |
| `limit` | integer | No | Items per page. Max 100. |

**Returns:** per checkout, the config, stats (viewed, clicked, opened, completed, revenue), the livemode label, and the ready-to-paste embed snippet.

---

## get\_embedded\_checkout\_snippet

Get only the paste-ready HTML embed snippet for one checkout. Read scope: `checkouts:read`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID |
| `id` | string | Yes | The embedded checkout id |

**Returns:** `snippet` (a two-line mount div plus one script tag that carries attribution by itself), `livemode`, and `isActive`. Paste the snippet verbatim where the checkout should render.

## create\_product

Create a product with one or more prices on a connected Stripe account, synced into Cortana immediately. Manage scope: `checkouts:manage`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID |
| `stripeAccountId` | string | Yes | The connected Stripe account (`acct_...`) |
| `name` | string | Yes | Product name the buyer sees |
| `description` | string | No | Product description |
| `prices` | array | Yes | 1 to 10 prices. Each: `amount` in DOLLARS (e.g. 49.99), `currency` (optional, defaults to the account currency), `recurring` (optional: `interval` of day, week, month, or year, plus `intervalCount`). Omit `recurring` for a one-time price. |

**Returns:** `localProductId`, `livemode`, `product`, and `prices`. Feed a `prices[].stripePriceId` straight into `create_embedded_checkout`.

---

## create\_embedded\_checkout

Create a Cortana embedded checkout and get its paste-ready snippet back in the same response. The checkout is live at once. Manage scope: `checkouts:manage`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID |
| `stripeAccountId` | string | Yes | The connected Stripe account that gets paid |
| `lineItems` | array | Yes | Prices to charge. Each: `priceId` and `quantity`. Any recurring price makes it a subscription. |
| `displayMode` | enum | Yes | `popup` shows a button that opens the checkout, `inline` embeds the form in the page, `hosted` uses a Stripe-hosted page. |
| `title` | string | No | Internal name, buyers never see it |
| `optionalItems` | array | No | Order bumps the buyer can tick on. Each: `priceId`, `quantity`, `label`. |
| `trialPeriodDays` | integer | No | 1 to 365. Requires a subscription price. |
| `buttonLabel` | string | No | Popup-mode button text |
| `successMessage` | string | No | Message shown after payment |
| `returnUrl` | string | No | Where the buyer goes after payment. Omit to stay on the page. |

**Returns:** the checkout, including `data.snippet` to paste into the page and the `livemode` flag.

---

## update\_embedded\_checkout

Update a checkout with merge semantics: send only the fields to change. Manage scope: `checkouts:manage`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID |
| `id` | string | Yes | The embedded checkout id |
| any create field | | No | Send to change it. Omit to keep the current value, send `null` to clear it. |
| `isActive` | boolean | No | `false` to pause, `true` to resume. Resuming re-validates the config. |

**Returns:** the updated checkout.

---

## deactivate\_embedded\_checkout

Turn a checkout OFF immediately. Manage scope: `checkouts:manage`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `businessId` | string | No | Your Business ID |
| `id` | string | Yes | The embedded checkout id |

**Returns:** `{ id, isActive: false }`. This is the kill switch: it always works with no validation, even if the prices were archived or Stripe is unreachable. The snippet stops rendering at once, history and stats stay intact. Reactivate later with `update_embedded_checkout` and `isActive: true`.

# Ad Management Tools

New. These tools let the assistant create and manage Meta ads. They require the ad management opt-in checkbox on the consent screen (see [Connect](/mcp/setup)).

<Warning>
  These tools spend money. Everything is created paused. Going live with `activate_entity` or changing budgets always requires your confirmation.
</Warning>

## Reads

| Tool | What it does |
| --- | --- |
| `list_ad_accounts` | Connected ad accounts the assistant can read or manage. |
| `get_ad_insights` | Platform-level ad performance pulled straight from the ad account. |

## Build and edit

| Tool | What it does |
| --- | --- |
| `create_campaign` | Create a new campaign (paused). |
| `create_ad_set` | Create an ad set with targeting, budget, and schedule (paused). |
| `create_creative` | Create an ad creative from uploaded media. |
| `create_ad` | Assemble a creative and ad set into an ad (paused). |
| `update_entity` | Edit an existing campaign, ad set, creative, or ad. |
| `activate_entity` | Set a campaign, ad set, or ad live. Requires your confirmation. |
| `pause_entity` | Pause a campaign, ad set, or ad. |

## Bring your own media

| Tool | What it does |
| --- | --- |
| `upload_ad_image` | Upload an image to the ad account from a URL or path. |
| `upload_ad_image_data` | Upload an image from raw image data. |
| `upload_ad_video` | Upload a video to the ad account. |
| `create_video_upload` | Start a resumable video upload session. |
| `get_video_status` | Check whether an uploaded video is ready to use. |
