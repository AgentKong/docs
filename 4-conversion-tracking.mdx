## <u>Conversion Sources</u>

A **conversion source** is what tells Cortana that an event has happened. A conversion (like *Lead*, *Booked Call*, or *Purchase*) is the bucket; a source is the pipe that fills it.

One conversion can have **many sources**. That is the normal setup, not an edge case. A single *Purchase* conversion might be fed by Stripe, Shopify, and a CSV import of historical orders all at once. Every source you add writes into the same conversion, and everything that lands there shows up in the Attribution Table against the ad, campaign, or channel that earned it.

Sources live at **Tracking → Conversion Setup**. You open (or create) a conversion, then click **Add Source** in the **Sources** section of that conversion.

### Available vs locked sources

The **Integration** dropdown lists all 23 source types. Four are always available because they do not depend on an outside tool:

**Forms / Appointments** · **Webhook** · **CSV Upload** · **Pixel**

The other 19 require their integration to be connected to this business first. Until it is connected, the entry is greyed out with a **padlock icon** and sorts to the bottom of the list. Clicking a locked entry does not select it. It shows an error toast such as `Please connect Stripe first. Go to Settings → Integrations to connect.`

The dropdown sorts **available sources A-Z first, then locked sources A-Z**. So on a business with everything connected, the whole list is simply A-Z. The accordions below follow that same A-Z order.

<Note>
  **Before you start**, make sure you have completed:

  - [**1) Connect Integrations**](/1-connect-integrations). Connect the tool you want to pull conversions from. A source stays locked until its integration is connected.
  - [**2) Setup Pixel**](/2-setup-pixel). This is required for the **Pixel** source, and strongly recommended for every other source, because the pixel is what ties a conversion back to the ad that caused it.
  - [**4.1) Conversion Set Up**](/4-conversion-setup). You need a conversion before you can attach a source to it.
</Note>

## Adding a source (works the same for every source)

<Note>
  The screenshots on this page are taken from real accounts, so account names, conversion names, form names and email addresses are deliberately blurred out. Nothing blurred is needed to follow the steps. Every label, dropdown and button you have to click is left readable.
</Note>

Every source is added the same way. Follow these six steps, then open your source in the catalog below for the fields that are specific to it.

<Steps>
  <Step title="Open Tracking for your business">
    From the dashboard, open the business you are working on and go to **Tracking**.
  </Step>

  <Step title="Go to the Conversion Setup tab">
    Click the **Conversion Setup** tab, then stay on its **Conversion Events** sub-tab (the other sub-tabs are **Conversions Dashboard**, **Meta Lead Forms**, and **Deleted Audit Log**).

    You now see a table of your conversions with the columns **Status**, **Conversion Name**, **Event Activity**, **Last Event**, **Sources**, **Column Presets**, and **Actions**.

    <Frame caption="Tracking → Conversion Setup → Conversion Events. Each row is a conversion; the Sources column shows how many sources feed it.">
      <img
        src="/images/ad-tracking/conversion-sources/shared/01-conversion-setup-tab.png"
        alt="The Conversion Setup tab on the Conversion Events sub-tab, listing conversions in a table with Status, Conversion Name, Event Activity, Last Event, Sources, Column Presets, and Actions columns, and a gear, duplicate, and trash icon in each row's Actions cell."
      />
    </Frame>
  </Step>

  <Step title="Open the conversion you want to feed">
    In the **Actions** column at the right of that conversion's row there are three icons: a **gear**, a **copy**, and a **trash can**. Click the **gear**.

    Clicking the row itself does nothing, and the small pencil that appears beside a conversion name on hover only renames it.

    The **Edit Conversion** dialog opens. If you do not have a conversion yet, create one first using [**4.1) Conversion Set Up**](/4-conversion-setup).
  </Step>

  <Step title="Click Add Source">
    Scroll down inside the **Edit Conversion** dialog to the **Sources** section and click the **Add Source** button (it sits next to a **Refresh** button).

    If this conversion has no sources yet, the section reads **"No sources created yet"**, followed by a hint telling you to click "Add Conversion Source" to create your first source. The button itself is labelled **Add Source**.

    <Frame caption="The Sources section of the Edit Conversion dialog. Add Source sits to the right, next to Refresh.">
      <img
        src="/images/ad-tracking/conversion-sources/shared/02-edit-conversion-add-source.png"
        alt="The Edit Conversion dialog scrolled to its Sources section, showing the existing sources table and the Add Source button beside a Refresh button."
      />
    </Frame>
  </Step>

  <Step title="Pick your source from the Integration dropdown">
    The **Create Conversion Source** dialog opens with an **Integration** dropdown at the top.

    <Warning>
      The **Integration** dropdown is pre-set to **Webhook**. It is not blank. If you want a different source you must change it, otherwise you will create a webhook by mistake.
    </Warning>

    Open the dropdown and pick your source. Available sources are listed A-Z first, then locked ones A-Z with a padlock. The form redraws to show the fields for whichever source you picked. Find that source in the catalog below for the rest of the setup.

    <Frame caption="The Integration dropdown. Connected sources sort A-Z at the top; locked ones sort A-Z below with a padlock.">
      <img
        src="/images/ad-tracking/conversion-sources/shared/03-integration-picker.png"
        alt="The open Integration dropdown in the Create Conversion Source dialog, listing all 22 conversion sources with the connected ones alphabetically first and the not-yet-connected ones greyed out with a padlock icon below them."
      />
    </Frame>
  </Step>

  <Step title="Save">
    Fill in the fields documented for your source, then click **Submit**. **Cancel** discards it.

    The new source appears in the **Sources** table of the conversion. You do not need to click **Save Changes** on the **Edit Conversion** dialog for the source itself to be created.
  </Step>
</Steps>

<Tip>
  You only see the **Add Source** button if your user has permission to manage tracking. If the button is missing entirely (rather than greyed out), ask an admin on the account to grant you tracking permissions.
</Tip>

    #### Importing refunds

    Turn **These are refunds** on when your export lists refund amounts as **positive numbers**. That is how most platforms export refunds. Hyros, for example, reports a refund as its own row with a positive amount, because it tracks refunds as a separate figure rather than as a negative sale. Uploaded as-is, those rows would add to your revenue.

    Leave it **off** when your file already uses minus signs, like `-49.00`. We read the minus sign automatically, so no toggle is needed.

    <Warning>
      **Export your refunds separately from your sales.** A CSV upload feeds one conversion at a time, and the refund option applies to **every row in the file**. Upload the sales file to your purchase conversion with the option off, and the refunds file to your refund conversion with the option on. If a single file mixes sales and refunds with no minus signs, there is no way to tell them apart. Split the export.
    </Warning>

    Turning it on twice is safe. The option makes values negative, it does not flip the sign back and forth. A file that already uses minus signs stays negative, and re-importing the same file will not turn refunds back into revenue.

    #### Number formats we accept

    You do not need to clean up your value column before uploading. All of these are read correctly:

    | What is in your file | What we record |
    | --- | --- |
    | `49.00` | 49.00 |
    | `1,234.56` | 1,234.56 |
    | `1.234,56` (European) | 1,234.56 |
    | `1 234,56` (French) | 1,234.56 |
    | `$1,234.56` | 1,234.56 |
    | `€1.234,56` | 1,234.56 |
    | `-49.00` | −49.00 |
    | `49.00-` (trailing minus, common in Excel exports) | −49.00 |
    | `(49.00)` (accounting style) | −49.00 |

    Currency symbols, thousands separators, and spaces are all handled. If a cell cannot be read as a number at all, that conversion's value is left blank rather than guessed.

    ### What Cortana creates for you

    | Source | Feeds the conversion | Revenue | Fires when |
    | --- | --- | --- | --- |
    | **Kajabi Purchase** | `purchase` (New Deals Closed) | New revenue | A one-time offer is bought, a subscription starts, or a payment plan starts |
    | **Kajabi Payment** | `all_payments` (LTV) | LTV | Every successful charge, including subscription rebills |
    | **Kajabi Form Submission** | `lead` | — | Any Kajabi form is submitted |

    <Warning>
      **Only one source carries cash revenue, and that is deliberate.** Kajabi fires a `purchase` event for every offer in a cart and a separate `order_created` event for the order as a whole. Subscribing to both would count the same checkout twice and inflate your revenue. **Kajabi Purchase** already covers every offer in the cart, itemised, so nothing is missed.
    </Warning>

    ### Checkout email capture (why this works when other tools miss it)

    Kajabi renders the email box on its checkout inside a web component, which means the real input is hidden from ordinary tracking scripts. A normal pixel scanning the page for input fields finds nothing and never learns who the buyer is.

    Cortana's pixel reaches into that component and reads the email **as the buyer types it, before they pay**. That matters twice over:

    - A buyer who lands straight on your checkout from an ad — with no prior opt-in — still gets matched to that ad. Tools that wait for the purchase webhook have nothing to match against and book the sale as organic.
    - A buyer who abandons partway through an upsell sequence is still identified.

    This ships inside the pixel itself. There is no extra snippet to paste and nothing to maintain — it is the reason **Paste 2** above is not optional.

    ### Disconnecting

    Disconnecting deletes the webhooks Cortana created in your Kajabi account and deactivates the three sources. Conversions already recorded are kept, and reconnecting later reuses the same webhook URLs.

## Refunds

When a customer gets refunded, Cortana records it automatically. There is nothing to switch on and no source to add.

### What happens

The first time a refund comes back through a connected payment source, Cortana creates a companion conversion named after the original, like **Purchase Refunds** or **New Deal Closed Refunds**. You will see it appear in **Tracking → Conversion Setup** next to the conversion it belongs to. You did not create it and you cannot delete it on its own.

Every refund from then on lands in that companion conversion as a negative amount.

### What it does to your numbers

Two things happen, and the difference matters.

**Your revenue goes down.** A \$470 sale followed by a \$470 refund nets to zero. Revenue, ROAS, and ROI all reflect what you actually kept, not what you invoiced.

**Your conversion count does not change.** A refund never counts as a conversion. Your cost per lead, cost per booked call, and cost per sale stay based on real conversions only.

<Note>
  That combination is deliberate. A refund is money leaving, not a conversion happening. If refunds counted as conversions, your cost per acquisition would look better every time a customer left.
</Note>

For the six that say yes, you do not need a separate refund source. Cortana matches the refund to the original sale and files it against whatever conversion that sale landed in.

### Sources that do not track refunds automatically

You have two options.

**Upload a CSV.** Export your refunds and import them with the **These are refunds** option turned on. See the CSV Upload source above.

**Send a negative value.** If you push conversions in by webhook or API, send the amount as a negative number. Cortana treats any negative as a refund and files it in the companion conversion for you.

### Seeing refunds in your reports

Refund columns are hidden by default so nothing about your existing view changes. To turn them on, open the Attribution Table, click **Columns**, and look under **Revenue**:

| Column | Shows |
| --- | --- |
| **Gross Revenue** | What you billed, before refunds |
| **Refunds** | What came back, as a negative |
| **Refund Rate** | Refunds as a percentage of gross |

Your existing **New Revenue** column is already net of refunds, with or without these turned on.

There is also a **Refunds** conversion column and a **Refund Rate** card you can add to your dashboard the same way you add any other.

<Warning>
  Turning refund tracking on for the first time changes historical numbers. Revenue and ROAS will drop for any period that contained refunds, because those periods were previously showing gross. Nothing is broken, the figures are now net. Tell your clients before they notice it themselves.
</Warning>

### Deleting a conversion that has refunds

Deleting a sale conversion also deletes its companion refunds conversion. Cortana warns you first and only when refunds actually exist. The same applies to a single payment: delete a payment that has a refund attached and the refund goes with it, so your balance stays true.

## Settings reference

These settings appear on more than one source. Where a source uses one, its accordion above says so.

### Source name

- **What it does:** labels the source in the conversion's **Sources** table and in logs.
- **Default:** most sources generate a name from the integration and event. Pixel sources fall back to **URL Parameter** or **Body Pixel** if you leave the field blank.
- **Recommendation:** name it after the real-world thing it tracks, including the platform, for example *Stripe - First Purchase (Main Account)*.
- **Caveat:** a vague name is the reason nobody can work out what a source does six months later.

### Event / When to track

- **What it does:** selects the single event that causes this source to fire.
- **Default:** none. Every source requires you to choose.
- **Recommendation:** one source tracks one event. To count several events, add several sources, or several conversions if you want to report on them separately.
- **Caveat:** picking two overlapping events on one conversion (like *Order Created* plus *Purchase (Paid)*, or *Payment Succeeded* plus *First Purchase*) double-counts. This is the most common configuration mistake.

### Account / workspace / store picker

- **What it does:** scopes the source to one connected account, sub-account, workspace, company, or store.
- **Default:** where only one is connected it is preselected and locked. GoHighLevel defaults to the primary sub-account.
- **Recommendation:** check it when you have several connected. Changing it clears every selection below.
- **Caveat:** the source only ever listens to the selected account. Activity in your other accounts silently produces nothing.

### Revenue tracking

- **What it does:** attaches money to the conversion. Appears as **Track revenue from opportunity** (GoHighLevel, Close.io), **Track revenue from deal** (HubSpot), **Track revenue (capture order value & currency)** (body pixel), or a revenue field picker (Salesforce).
- **Default:** off for GoHighLevel, Close.io, HubSpot, and the body pixel. Payment sources like Stripe, Whop, Shopify, WooCommerce, Shopier, and Fanbasis always carry revenue.
- **Recommendation:** on for anything that represents money changing hands, off for leads and bookings.
- **Caveat:** CRM opportunity values are one-time cash collected, not recurring revenue. For subscription revenue use Stripe or Whop as the source of truth.

### Currency

- **What it does:** sets which currency a source's revenue is recorded in when the source does not supply one itself.
- **Default:** **USD**.
- **Recommendation:** set it to the currency the underlying records are actually in. For GoHighLevel invoices it is only used when an invoice does not specify its own.
- **Caveat:** getting this wrong does not error, it silently misstates revenue. The display currency in the Attribution Table is a separate per-business preference.

### Product filter

- **What it does:** restricts a payment source to specific products.
- **Default:** empty, which means **all products, including ones you create later**.
- **Recommendation:** leave it empty unless you genuinely need to isolate a product. An empty filter is future-proof.
- **Caveat:** once you select specific products, new products are **not** picked up automatically. You have to come back and add them.

### Payment Filters (qualification rules)

- **What it does:** only counts a payment when it matches your rules. Available on Stripe, Whop, and Fanbasis. The section explains itself in the dialog: *"Only count payments matching these rules, e.g. only payments of $100 or more. Filtered payments are still recorded and count toward LTV, but won't create this conversion event or be sent to ad platforms."*
- **Fields you can build rules on:** **Payment Amount** (number), **Currency**, **Customer Email**, **Product Name**, and **Billing Reason**.
- **Options:** an **Enable Payment Filter** toggle (*"Only matching payments will create conversions"*), and a **Payment must match** selector offering **ALL rules** (AND) or **ANY rule** (OR).
- **Default:** disabled.
- **Recommendation:** the most useful rule by far is a minimum **Payment Amount**, to exclude small test charges or trial authorisations from a revenue conversion.
- **Caveat:** a filtered-out payment is not deleted. It still counts toward lifetime value, it just does not fire this conversion or get sent to Meta, Google, or TikTok. Rules are also evaluated when the payment arrives, so turning them on does not retroactively remove conversions that already counted.

### Lead Filters (form qualification rules)

- **What it does:** only counts a form or survey submission when the answers match your rules. Available per form on Typeform, Tally Forms, HubSpot forms, and GoHighLevel forms, surveys, and appointments.
- **Default:** none, so every submission counts.
- **Recommendation:** use it to build a *Qualified Lead* conversion separate from raw *Lead* volume, for example only counting people who picked a budget above a threshold.
- **Caveat:** rules run against the field catalog of that specific form. If you change the form's questions, revisit the rules.

### Dedup window

- **What it does:** stops the same contact converting twice within a set period. Used by the **URL Parameter** and **Body Tracking Snippet** pixel sub-types.
- **Options:** a number plus **Seconds**, **Minutes**, **Hours**, or **Days**.
- **Default:** shown in the picker when you open it; the enforced minimum is **30 seconds**.
- **Recommendation:** at least **2 days** for lead and qualified-lead pixels.
- **Caveat:** values under 30 seconds are clamped on save. Identity is matched by cookie, form data, and device fingerprint, so a genuinely different person on the same device may be treated as a repeat.

### One entry per stage, per contact

- **What it does:** on the GoHighLevel **Opportunity Stage Changed** event, records a contact only once per stage.
- **Default:** off.
- **Recommendation:** turn it on unless you specifically want to count re-entries.
- **Caveat:** with it off, a deal moved back and forth between stages logs an entry every time.

### Track all forms (Meta Ads)

- **What it does:** makes the source a catch-all for every enabled lead form, including forms you create later.
- **Default:** on.
- **Recommendation:** leave it on. It is the only setting that picks up new forms without you revisiting this screen.
- **Caveat:** only one source can hold the catch-all. If another source already has it, the toggle is locked off and you must select specific forms.

## Tips and caveats

<Tip>
  **One conversion, many sources is normal.** A *Purchase* conversion fed by Stripe, Shopify, and a historical CSV import is a perfectly standard setup. Add as many sources as you need.
</Tip>

<Warning>
  **A greyed-out source with a padlock is not a bug.** It means that integration is not connected to this business. Connect it at **Settings → Integrations** (see [**1) Connect Integrations**](/1-connect-integrations)) and come back. The picker sorts locked sources to the bottom, so if a source you expected is missing, scroll down.
</Warning>

<Note>
  **Some sources are instant, some are polled.** Webhook-driven sources (Shopify, Stripe, Whop, WooCommerce, HubSpot, GoHighLevel webhooks) arrive within seconds. Polled sources arrive on a schedule:

  | Source | Frequency |
  | --- | --- |
  | GoHighLevel forms and surveys | Every 5 minutes |
  | iClosed | Every 5 minutes |
  | Salesforce | Every 5 minutes |
  | Cal.com | Every 15 minutes |
  | Shopier | Every few minutes |

  Do not conclude a source is broken until at least one full poll cycle has passed.
</Note>

<Warning>
  **Watch for double counting.** The overlapping pairs that catch people out most often are *Payment Succeeded* with *First Purchase* (Stripe, Whop, Fanbasis, Shopier), and *Order Created* with *Purchase (Paid)* (Shopify). Put each of a pair on its own conversion, never both on one.
</Warning>

<Tip>
  **CSV files need an email or a phone number on every row.** Rows with neither are skipped, because there is no way to identify the person or attribute them to an ad. The preview step tells you how many rows will be skipped before you commit.
</Tip>

    Some sources will not let two sources in the same conversion listen to the same event. Shopify says *"All available Shopify events have already been added to this conversion. Create a new conversion to track additional events."* GoHighLevel and Tally instead hide the forms that are already attached.

    **Fix:** either edit the existing source instead of adding a new one, or create a separate conversion for the additional event.
  </Accordion>

  <Accordion title="I connected the integration but no events are arriving">
    Work through these in order:

    1. **Wait for the poll cycle.** Polled sources take up to 5 or 15 minutes. See the frequency table above.
    2. **Click Refresh.** The **Sources** table has a **Refresh** button that re-reads counts.
    3. **Check the Requests column** on the source row. For webhook sources this opens the logs showing test, failed, and successful requests, with a reason on each failure. The most common failure is a payload carrying no name, email, or phone, which makes the person unidentifiable.
    4. **Meta Ads specifically**: verify Lead Access. Go to **business.facebook.com/settings → Integrations → Lead Access**, click your page, open **CRMs**, and confirm **Cortana AI** is assigned. Meta blocks lead delivery silently when it is not, and nothing inside Cortana will indicate this.
    5. **WooCommerce specifically**: check your **Count orders with status** selection actually includes the status your gateway uses.
    6. **HubSpot Custom Field Updated specifically**: this needs the property subscribed to Cortana's HubSpot app `contact.propertyChange` events. Contact support to add the subscription.
    7. **Manually-connected Shopify**: the webhook must be created in your Shopify admin using the URL and secret shown in the setup card. Save stays gated until a test event arrives.
    8. **Reconnect the integration.** Expired tokens frequently fail quietly. Calendly refresh tokens in particular are single-use.
  </Accordion>

  <Accordion title="I am seeing duplicate or inflated conversions">
    Usual causes, most common first:

    1. **Two overlapping events on one conversion.** *Payment Succeeded* plus *First Purchase*, or *Order Created* plus *Purchase (Paid)*. Split them onto separate conversions.
    2. **Pixel dedup window too short.** Someone refreshing your thank-you page counts every time. Raise the dedup window to at least 2 days.
    3. **GoHighLevel stage re-entries.** Turn on **Only one entry per stage, per contact**.
    4. **The same event arriving through two routes**, for example a Shopify order counted by both the Shopify source and a webhook you built yourself. Keep one route.
    5. **A CSV import re-run.** Use the **Remove duplicates** option in the Clean step.
  </Accordion>

  <Accordion title="Revenue is missing or wrong">
    - **Revenue is zero on a CRM source**: the **Track revenue** checkbox is off. It is off by default on GoHighLevel, Close.io, and HubSpot.
    - **Revenue is zero on a body pixel**: **Track revenue (capture order value & currency)** is off, or your page does not expose purchase data for auto-detection. Pass value and currency manually in the snippet.
    - **Revenue is in the wrong currency**: check the source's currency setting, which defaults to **USD**. This is separate from the Attribution Table's display currency.
    - **WooCommerce revenue far too low**: your **Count orders with status** list is missing the status your gateway parks orders in.
    - **Salesforce revenue is zero**: check which field is configured as the revenue field, and that revenue is not disabled on the source.
  </Accordion>

  <Accordion title="The Add Source button is not there">
    The button only renders for users with permission to manage tracking. If you can see the conversion but not the **Add Source** button, ask an account admin to grant you tracking permissions.
  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="How do I track Stripe payments?">
    Connect Stripe at **Settings → Integrations**, then open your revenue conversion, click **Add Source**, pick **Stripe**, choose your **Stripe Account**, and pick a **Stripe Event**. For total revenue use **Payment Succeeded**; for new customers only use **First Stripe Purchase**. Optionally filter to specific products or add a minimum amount under **Payment Filters**, then click **Submit**.
  </Accordion>

  <Accordion title="Why is Whop locked?">
    Whop, like the other 17 integration-backed sources, stays greyed out with a padlock until Whop is connected to this business. Connect it at **Dashboard → Integrations** and the entry unlocks and moves up into the A-Z list. This is the same reason any source shows a padlock.
  </Accordion>

  <Accordion title="Can one conversion have two sources?">
    Yes, and it is the normal setup. A *Purchase* conversion is often fed by Stripe, Shopify, and a CSV import at the same time. Everything written by any of those sources lands in the same conversion.

    The one thing to avoid is two sources tracking the **same** event, which double-counts. Overlapping events (like *Payment Succeeded* and *First Purchase*) belong on separate conversions.
  </Accordion>

  <Accordion title="What is the difference between URL Parameter and Body Tracking Snippet?">
    Both are the **Pixel** source, chosen from the **Pixel Type** dropdown.

    **URL Parameter** gives you a short parameter such as `?cor-conv=abc12345` that you append to a URL. The conversion fires when that page loads. Use it when you control a redirect, for example sending qualified leads to a specific thank-you page.

    **Body Tracking Snippet** gives you an HTML snippet you paste into the `<body>` of a page. It fires silently on page load with nothing visible in the address bar. Use it when you can edit the page's code. Only the body snippet can capture order value and currency.

    Both require your Cortana tracking script to already be on the page.
  </Accordion>

  <Accordion title="My source is not in the list. Where is it?">
    Locked sources sort to the bottom of the dropdown, below every available one, so scroll down. If it is there with a padlock, its integration is not connected yet.

    If the platform you use is not one of the 22 at all, use a **Webhook** source. Any tool that can send an HTTP request, including Zapier, Make.com, and n8n, can feed a conversion that way.
  </Accordion>

  <Accordion title="How do I import historical leads or sales?">
    Use **CSV Upload**, which is always available. Name the source, upload a file up to 100 MB, map your columns (every row needs an email or a phone number, plus a conversion date), choose whether to remove duplicates, review the preview, and start the import.

    Set up **AI Ad Optimization** first if you want the imported history sent back to your Meta pixel to train it.
  </Accordion>

  <Accordion title="I imported refunds and my revenue went up instead of down.">
    Your file listed the refunds as positive numbers and the **These are refunds** option was off. Re-import the file with the option on. If the wrong rows are already in your account, contact support and we will correct them.
  </Accordion>

  <Accordion title="Do I need to add minus signs to my CSV before uploading?">
    No. Either use the **These are refunds** option, or leave the minus signs your export already has. Both work.
  </Accordion>

  <Accordion title="Can I put sales and refunds in the same file?">
    Only if the refunds already carry minus signs. Otherwise export them separately. The refund option applies to every row in the file, so a mixed file without minus signs cannot work.
  </Accordion>

  <Accordion title="My totals looked wrong on a past import.">
    Older imports could misread values containing commas or unusual minus signs. Re-importing the file now will read them correctly. Reach out if you need help checking a past import.
  </Accordion>

  <Accordion title="How do I know a source is actually working?">
    Open the conversion and look at its **Sources** table, which shows each source's **Status**, **Requests**, and **Data**. Click **Refresh** to re-read the counts. For webhook sources, the **Requests** column opens the full logs with test, failed, and successful requests, including the raw payload and a reason for any failure.

    Then fire a real test: submit the form, book the meeting, or make a small payment, and watch the count change. Remember polled sources can take up to 15 minutes.
  </Accordion>

  <Accordion title="Do I still need the pixel if I use an integration?">
    Yes. The integration tells us *that* a conversion happened; the pixel is what ties it back to the ad, campaign, and click that caused it. Without the pixel, conversions still count but attribution is much weaker. See [**2) Setup Pixel**](/2-setup-pixel) and [**5) URL Parameters (CRITICAL)**](/5).
  </Accordion>
</AccordionGroup>
