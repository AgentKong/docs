---
title: "Appointment and deal events"
description: "Get a signed message the moment an appointment is booked, moved, cancelled or marked, or a deal is added, moved, won or lost, whoever made the change."
---

Your endpoint (Zapier, Make, n8n, or your own app) can receive one signed message for every real change to an appointment or a deal. It comes whichever way the change was made: in the app, on your booking page, from the Chrome extension, through the API, by Claude or ChatGPT, by a CRM's sync, or by GoHighLevel, Calendly or iClosed.

Each message says what changed, who changed it and from where, each field before and after, and the appointment or deal itself.

## The seven events

| Event | Sent when |
| --- | --- |
| `appointment.booked` | A new appointment is booked |
| `appointment.rescheduled` | An appointment moves to a new time |
| `appointment.cancelled` | An appointment is cancelled (a cancel that also moved its time is this one event) |
| `appointment.status_changed` | An appointment is marked shown, not shown or completed, or set back to booked |
| `deal.created` | A new deal is added |
| `deal.moved` | A deal moves to another stage |
| `deal.status_changed` | A deal is marked won, lost or abandoned, or reopened. A move to another stage at the same moment comes in this one event, with `changes.stage`. |

One message per change: a deal moved five times sends five messages, each with its own `id`.

### When nothing is sent

- A change that was refused, that changed nothing, or that did not go through.
- An edit these events do not cover: an appointment's title, notes, place or meeting link, or handing it to another rep; a deal's value, name, owner or custom fields; deals moved because their stage was deleted.
- Records brought in by an import.
- A deal your CRM made more than 24 hours before Cortana copied it, or one your CRM sends without the time it was made. A deal your CRM makes live sends `deal.created`.
- A GoHighLevel, Calendly or iClosed booking copied after the fact: Cortana sends `appointment.booked` for one only while it is live, before the meeting starts and within 24 hours of when it was booked there. The older bookings copied when you first connect a calendar, or when a sync catches up, send nothing. A GoHighLevel booking Cortana first hears about through a later update to it sends nothing either.
- [Cortana's own test bookings](/cortana-test-bookings).

## Subscribe

Your endpoint receives these events only when it names them. An endpoint subscribed to `*` (every event) does **not** get them: add each one you want.

<Tabs>
  <Tab title="In the app">
    Go to your business, then **Settings**, then the **Webhooks** tab. Add or edit an endpoint and tick the appointment and deal events you want. The signing secret is shown once, when you add the endpoint.
  </Tab>
  <Tab title="With the API">
    `POST /api/v1/businesses/{businessId}/webhooks` with your `targetUrl` and the `events` you want. The answer carries the endpoint's `signingSecret`, shown only here and when you rotate it with `POST …/webhooks/{webhookId}/rotate-secret`. Change an endpoint with `PATCH …/webhooks/{webhookId}`.

    ```json
    {
      "targetUrl": "https://example.com/hooks/cortana",
      "events": ["appointment.booked", "appointment.cancelled", "deal.status_changed"]
    }
    ```

    The key needs `webhooks:write`, and the read scope of each family it subscribes to: `appointments:read` for the `appointment.*` events, `deals:read` for the `deal.*` events. That is checked when you create the endpoint and on every change to it, a new URL or switching it back on included, against the events it holds. A key without it is refused with `403` "Insufficient scope. Required: appointments:read", and nothing is saved.
  </Tab>
</Tabs>

## What a message looks like

Every message is a `POST` with a JSON body and these headers:

| Header | Value |
| --- | --- |
| `X-Cortana-Event` | The event, such as `deal.status_changed` |
| `X-Cortana-Delivery` | This delivery's id |
| `X-Cortana-Signature` | `t=<unix seconds>,v1=<signature>` |

To check a message came from Cortana, compute an HMAC-SHA256 of `<t>.<the raw body>` with your endpoint's signing secret, as hex, and compare it with `v1`:

```js
import crypto from 'node:crypto';

function isFromCortana(rawBody, header, signingSecret) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  const expected = crypto.createHmac('sha256', signingSecret).update(`${parts.t}.${rawBody}`).digest('hex');
  return parts.v1.length === expected.length && crypto.timingSafeEqual(Buffer.from(parts.v1), Buffer.from(expected));
}
```

### What each part holds

| Field | What it is |
| --- | --- |
| `id` | The change's own id. Each change has one, so use it to tell changes apart. |
| `data.change` | The change as the record's **History** panel reads it: `what` and the whole `line`, `at` (UTC) and `when` (on the business's clock, in `timeZone`), and `action`, the kind of change (`deal.won`, `deal.lost`, `deal.abandoned` or `deal.reopened` for a `deal.status_changed`). |
| `data.actor` | Who made the change: `kind` (`person`, `contact` for a lead, `api_key`, `ai`, `crm_sync`, `automation` or `system`), `name`, `forPerson` (the teammate an AI acted for) and `where` ("in the app", "via API", "on the booking page", "for Sarah Lee"; `null` for a sync). An email never stands as a name: a teammate with no name on file reads "A teammate", a lead "A lead". |
| `data.changes` | Only the fields this change moved, each with `before` and `after` as they were at that moment. Times in ISO 8601, statuses as the API names them, a deal's `stage` and `owner` as `{ id, name }`. On a new appointment or deal it holds every field it was made with, each `before` `null`. A long text arrives cut at 1,000 characters, ending in "…". If one side of the change was over 8,000 characters, `changes` is `{}`: read the record. |
| `data.appointment` or `data.deal` | The record as `GET` answers it in the [API](/api-reference/endpoint/get-deal). It is read when the message is sent, so it can already show a later change: read `changes` for the moment of this one. |
| `data.contact` | The contact, the same block as `contact.created` carries. |

A message over 32 KB is trimmed: an appointment's `notes` and `description` become `null`, a deal's `customFields` become `[]` with `customFieldsTruncated: true`, and the contact's `customFields` become `{}`.
