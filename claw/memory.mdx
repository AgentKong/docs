## Overview

Memory is what lets a Claw agent get better over time instead of starting from zero on every task. It has three layers:

- **Recall** — the agent reads back its own past runs. Always on, never needs approval.
- **Durable facts** — the agent saves specific facts you approve, and reuses them later.
- **Semantic memory (mem0)** — optional, meaning-based long-term memory across everything an agent has learned.

Memory is **per-agent**: one agent can't read another's memories.

<Note>
  There's no separate "Memory" screen in the Claw workspace — memory happens **during runs**. You review what an agent has done in its conversation history, and you approve every fact it wants to keep.
</Note>

## Recall — the agent remembers its own work

Every run is recorded: the steps taken, the tools called, and what was found. The agent can look back over its own history to answer questions like *"what did you find last week?"* or to avoid repeating work.

Recall is **read-only** and **never** needs approval — it's just the agent reading its own past.

## Durable facts — saved with your approval

When an agent learns something worth keeping — *"the monthly report goes to #revenue-updates"*, *"this client's fiscal year starts in February"* — it can propose saving it as a durable memory.

<Warning>
  **Saving a fact always asks for your approval.** Writing to memory is a sensitive action, so the agent pauses and shows you exactly what it wants to remember before it saves. See [Approvals & billing](/claw/approvals-and-billing).
</Warning>

Facts are keyed by topic, so updating a topic **overwrites** the old value instead of piling up duplicates.

## Semantic memory (mem0)

For richer, meaning-based long-term memory, connect **mem0** at the business level:

<Steps>
  <Step title="Add mem0 to the business">
    Go to **Settings → Integrations** for the agent's home business and connect **mem0** with your mem0 API key. The key is stored in Cortana's encrypted vault.
  </Step>
  <Step title="Agents gain semantic recall">
    Once the business has mem0 connected, an agent's saved facts are mirrored into a **private mem0 namespace** for that agent — giving it meaning-based lookup across everything it has learned, not just exact-topic matches.
  </Step>
</Steps>

<Note>
  mem0 is configured on the business through the Integrations tab — not inside the individual agent editor. The API key lives on the agent's home business and is never exposed to the agent.
</Note>

## Settings reference

| Layer | Where it's controlled | Approval to write? | Scope |
|---|---|---|---|
| **Recall** | Automatic — no setup | Never (read-only) | The agent's own past runs |
| **Durable facts** | Proposed by the agent during a run | Yes, every save | Per-agent, keyed by topic |
| **Semantic memory (mem0)** | Settings → Integrations (business) | Same as durable facts | Private mem0 namespace per agent |

## Troubleshooting

<AccordionGroup>
  <Accordion title="The agent doesn't remember something from a past chat">
    Recall reads the agent's **own** runs. If the earlier work was done by a different agent, this agent can't see it — memory is per-agent. Reopen the original conversation, or ask the agent that did the work.
  </Accordion>

  <Accordion title="It keeps asking me to approve saving a memory">
    That's by design — every write to durable memory needs approval. Approve the ones worth keeping; deny the rest. There's no way to make memory writes silent except by running unattended.
  </Accordion>

  <Accordion title="Semantic memory isn't working">
    Confirm **mem0** is connected under **Settings → Integrations** for the agent's home business and that the API key is valid. Without a connected mem0 integration, agents fall back to recall and durable facts only.
  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="Can one agent read another agent's memory?">
    No. Memory is scoped per-agent. To share knowledge, put it in a [skill](/claw/skills) or a [recipe](/claw/recipes), which do travel between agents.
  </Accordion>

  <Accordion title="Where can I see what an agent remembers?">
    Recall is visible in the agent's conversation history — reopen past conversations to see what it did. Durable facts are the ones you approved during runs.
  </Accordion>

  <Accordion title="Is my mem0 API key visible to the agent?">
    No. It's stored in the encrypted vault on the business and injected server-side; it never appears in the agent's context or the run transcript.
  </Accordion>

  <Accordion title="Do I need mem0 to use memory?">
    No. Recall and durable facts work with no setup. mem0 only adds meaning-based semantic lookup on top.
  </Accordion>
</AccordionGroup>
