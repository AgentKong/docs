## REST API keys

API keys authenticate the public REST API and any integration you build yourself. Every request sends the key as a Bearer token. Keys are shown once and start with `sk-ak-`.

<Steps>
  <Step title="Open Settings">
    Go to Settings, then API Keys, then Generate New Key in your Cortana dashboard.
  </Step>
  <Step title="Pick a permission preset">
    Choose one of two one-click presets, or set permissions a la carte. New keys default to Read Only.
  </Step>
  <Step title="Generate and copy">
    Give the key a name, click Generate, and copy it immediately. It will not be shown again.
  </Step>
</Steps>

### A la carte scopes

Instead of a preset, scroll the permission list and check the specific scopes you need, then click Generate. Each scope below is one of those a la carte options.

| Scope | Grants |
| --- | --- |
| `contacts:read` | List and search contacts |
| `contacts:write` | Create, update, and delete contacts |
| `conversations:read` | List conversations, read messages and call logs |
| `conversations:write` | Update conversation metadata |
| `messages:read` | Read message history |
| `messages:write` | Send messages |
| `agents:read` | List and view agent configurations |
| `agents:write` | Create, update, and delete agents |
| `appointments:read` | List and view appointments, calendars and their open times, and read their history |
| `appointments:write` | Book, change and cancel appointments; create calendars and change their settings, hours and team |
| `deals:read` | List pipelines, their stages and deals, and read their history |
| `deals:write` | Add, change, move, win, lose and reopen deals; add, rename and reorder stages |
| `conversions:read` | View conversion entries and configs, and read a conversion's history |
| `conversions:write` | Create conversion entries |
| `tracking:read` | View tracking sessions |
| `tags:read` / `tags:write` | Manage tags |
| `custom_fields:read` / `custom_fields:write` | Manage custom fields |
| `attribution:read` | Full attribution table, UTMs, presets, LTV |
| `metrics:read` | List custom metrics, check a formula, and read their history. Their values also need `attribution:read`. |
| `metrics:write` | Create and change custom metrics, and turn them off or back on |
| `stripe:read` | Stripe payments, subscriptions, customers, metrics |
| `shopify:read` | Shopify orders, customers, products, analytics |
| `whop:read` | Whop payments, customers, memberships |
| `meetings:read` | Read meetings and Fathom data |
| `businesses:write` | Create businesses, list agency business templates, and update a business's Business Info |
| `webhooks:read` / `webhooks:write` | Read, or add, change and remove, your webhook endpoints. Subscribing an endpoint to [appointment or deal events](/webhook-events) also needs `appointments:read` or `deals:read`, and `contacts:read`: each event carries its contact. |
| `embedded_checkouts:read` / `embedded_checkouts:write` | Read, or create and change, embedded checkouts. Write can sell on your connected Stripe. |
| `stripe:write` | Create products and prices on your connected Stripe accounts (**Product Creation** on the key screen) |

<Note>
  Programmatic onboarding (`businesses:write`) is included in All Access, or you can select it on its own a la carte.
</Note>

### Find your Business ID

Most routes are per business (`/api/v1/businesses/{businessId}/...`). Your Business ID is in the dashboard URL:

```text
https://app.usecortana.ai/business/cf3383a0-55f6-45d8-ab57-484edd63770c/tracking
```

The UUID after `/business/` is your Business ID.

## When your admin turns off API and AI tools

{/* last-verified: 2026-10-06 · permission key apiAccess (Control Centre > Users > Manage Permissions) */}

Your account admin can switch off **API & AI tools** for your login. While it is off:

- Every API key you made stops working. Requests answer `403` with "Your account admin has turned off API and AI tools for you."
- You cannot generate a new API key. Your **API Keys** page shows the same sentence in place of the button.
- Your Claude or ChatGPT connection to Cortana stops working (each call is refused with `401`, as for a disconnected app), and you cannot connect a new one.

Nothing is deleted. When your admin switches it back on, your API keys work again straight away. A Claude or ChatGPT connection may ask you to reconnect once. Account owners are never affected, and the Cortana Chrome extension keeps working when it is connected with **Sign in with Cortana AI**.

## Connecting an AI assistant (MCP)

To use Cortana inside Claude, ChatGPT, or Codex, add the MCP connector. This path uses OAuth, so there is no API key to copy or store.

<Steps>
  <Step title="Add the connector">
    In your AI tool, add a custom connector using the MCP URL `app.usecortana.ai/api/mcp`.
  </Step>
  <Step title="Log in to Cortana">
    You are sent to Cortana to sign in, the same account you use for the dashboard.
  </Step>
  <Step title="Pick your businesses">
    Choose which business or businesses the assistant is allowed to access.
  </Step>
  <Step title="Approve permissions">
    Review the consent screen and approve. By default the assistant reads your data, books, moves and cancels appointments, edits your calendars, works your pipelines and deals, edits custom metrics, sets up conversions and Meta tracking, edits your Business Info and sees who changed what, each with your own permissions in Cortana.
  </Step>
</Steps>

<Warning>
  Ad management (create, launch, and spend) is a separate opt-in checkbox on the consent screen. Leave it unchecked if you don't want the assistant to create or launch ads.
</Warning>
